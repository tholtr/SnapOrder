**工具在真实 Redis（6380）上手工跑了 12 个场景**，不只是单测：

- `key` 模式跑完 `KEYS risk:bl:*` 为空——只算键的路径**一个字节都没写**
- `add` → `TYPE=set EXISTS=1 SCARD=1 TTL=-1 SISMEMBER=1`，退出码 0；重复 `add` 报「已存在，本次只是复核」
- `remove` → 「已解除（此前是黑名单）」，`EXISTS=0`；重复 `remove` → 「本来就不在黑名单里，无事发生」
- 手写 `SET risk:bl:user:8888 1` 后 `add` → `WRONGTYPE` 且**退出码 3**（没有静默成功）；随后对同一个**字符串类型**的键 `remove` → 成功（F-18 的取舍由此得到实证）
- userId 写错 / 未知动作 / 未知维度 / 密钥缺失 → 全部退出码 2；`DASH_REDIS_PORT=6399` → 退出码 3

跑完清干净，Redis 无残留键。
